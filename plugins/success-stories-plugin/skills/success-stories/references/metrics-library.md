# Metrics Library

Which metrics to lead with, by product category. Lead with the metric in the "Hero" column.

## Operational SaaS (VehicleOS, FleetOS, FacilityOS)

| Category | Hero metric | Supporting metrics |
|---|---|---|
| Time | Hours saved per month | Records migrated, frequency of use |
| Cost | RM saved in avoided repairs/fees | Cost per asset, TCO reduction |
| Reliability | Uptime % | MTBF, missed maintenance events |

**Never claim:** "X% improvement" without a baseline. Always show before/after.

## Compliance / Corporate (SenangBoss, CorpOS)

| Category | Hero metric | Supporting metrics |
|---|---|---|
| Speed | Filing turnaround (days → hours) | Documents processed |
| Cost | Professional fees replaced (RM) | Hourly rate × hours saved |
| Accuracy | Audit findings avoided | First-pass approval rate |

**Malaysian context:** CoSec typically RM 1,500–5,000/month retainer; replacing that is the cleanest RM-saved number.

## Financial (EmasOS, WealthOS, RetireEmas)

| Category | Hero metric | Supporting metrics |
|---|---|---|
| AUM | Total managed value | Customer count, avg balance |
| Access | Onboarding time (days → minutes) | KYC pass rate |
| Performance | Net yield % | Rolling 12-mo return |

**Regulatory note:** Any performance claim needs a disclaimer. Include "past performance is not indicative of future results."

## Communication (ChatOS, FunnelOS, MarketingOS)

| Category | Hero metric | Supporting metrics |
|---|---|---|
| Speed | First-response time | Resolution time |
| Conversion | Close rate % | Funnel stage progression |
| Volume | Leads handled per agent | Automation rate |

## Developer / Infra (McpOS, DB-OS, LogOS, AgentOS)

| Category | Hero metric | Supporting metrics |
|---|---|---|
| Velocity | Deploys per week | Lead time for changes |
| Reliability | Uptime % / SLO | MTTR, incidents per month |
| Efficiency | Engineering hours saved | Tickets auto-resolved |

## Conversion benchmarks (for sanity-check)

| Claim | Sanity range |
|---|---|
| Hours saved | 5–40 hours/month per user is normal; 100+ needs explanation |
| Cost savings | 20–60% is typical; 80%+ needs a specific feature story |
| Revenue uplift | 10–30% is strong; 50%+ is rare and needs context |
| Onboarding speedup | 10x is common going from manual→automated; 100x means they weren't really doing it before |
